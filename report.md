# Отчёт о сравнительном тестировании V1 и V2

**Вариант:** A — Новичок

**Цель:** проверить работу двух независимо разработанных мини-трекеров учебных задач по одинаковым сценариям T1–T5.

## Результаты тестирования

| Запрос | Ожидаемый результат | V1 | V2 |
|---|---|---|---|
| **T1. Исходные данные** | 3 задачи, 8 часов, выполнено 2 часа. Прогресс 25%. | Ошибка: первоначальный прогресс 33%. Исправлено на 25%. | Корректно: 25%. |
| **T2. Выполнение задачи** | При отметке «Практики» выполненной прогресс составляет 75%. | После исправления расчёт соответствует требованиям. | Отработал по вводным данным. |
| **T3. Фильтрация** | При выборе «Активные» отображаются 2 задачи, общий прогресс остаётся 25%. | Первоначально отображался некорректный общий прогресс 33%. Исправлено. | Корректно: 2 активные задачи, прогресс 25%. |
| **T4. Ошибки ввода** | Некорректные значения отклоняются. Допустимые часы: 0,5–24 с шагом 0,5. | Выявлено несоответствие ограничений ввода исходным требованиям. Исправлено. | Отработал по вводным данным. |
| **T5. Удаление задач** | После удаления всех задач: 0 часов и 0% выполнения. | После исправлений работал корректно. | Отработал по вводным данным. |

## Процесс исправления V1

**Шаг 1. Расчёт прогресса**

В исходной версии прогресс рассчитывался на основании количества выполненных задач, что приводило к результату 33% при выполнении одной задачи из трёх.

Был направлен дополнительный запрос на изменение логики. После исправления прогресс стал рассчитываться по сумме часов выполненных задач относительно общего количества часов.

Результат: 2 / 8 × 100 = 25%.

**Шаг 3. Фильтрация**

При выборе активных задач приложение отображало две невыполненные задачи, но общий процент выполнения был некорректным.

После исправления формулы прогресс стал независимым от количества видимых задач и рассчитывался по всем задачам.

**Шаг 4. Проверка введённых часов**

В первой реализации обнаружено несоответствие диапазона и шага вводимых часов требованиям.

Был отправлен дополнительный запрос на исправление ограничений: от 0,5 до 24 часов с шагом 0,5.

После доработки HTML-код обновлён.

## Итоговый вывод

В ходе сравнения двух подходов были выявлены различия в качестве первоначальной реализации.

**V1 — разработка по прямому запросу:** обнаружены ошибки в сценариях 1, 3 и 4. Для устранения несоответствий потребовались дополнительные обращения к ИИ и изменение программного кода.

**V2 — разработка по спецификации:** приложение отработало по заданным входным требованиям без указанных ошибок первоначальной V1.

После исправлений обе реализации работали корректно, согласно итоговой пользовательской проверке.

**Основной вывод:** предварительная спецификация помогает формализовать требования и уменьшить число ошибок при первоначальной реализации. При этом ручное тестирование остаётся необходимым для обоих подходов.
